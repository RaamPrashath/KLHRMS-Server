# Configuration Guide

This boilerplate is intentionally configuration-first. You should select auth mode, traffic controls, and observability using environment variables.

## Auth Providers

Set `AUTH_PROVIDER` to one of:

- `custom_jwt`: App-managed login/register, token issuance from `/api/v1/auth/login`.
- `api_key`: Static API key auth for service-to-service access.
- `entra`: Microsoft Entra ID bearer token validation.

### 1) custom_jwt

Required:

- `JWT_SECRET_KEY`
- `JWT_ALGORITHM` (default `HS256`)
- `JWT_ACCESS_TOKEN_EXPIRE_MINUTES`

Behavior:

- `/api/v1/auth/register` and `/api/v1/auth/login` are enabled.
- Protected routes use bearer token generated by this app.

### 2) api_key

Required:

- `STATIC_API_KEY_HEADER` (default `x-api-key`)
- `STATIC_API_KEY_VALUE`
- `AUTH_FALLBACK_USER_ID`

Behavior:

- Send the API key header on each protected request.
- App maps authenticated requests to `AUTH_FALLBACK_USER_ID` for authorization context.

### 3) entra

Required:

- `ENTRA_TENANT_ID`
- `ENTRA_CLIENT_ID` or `ENTRA_AUDIENCE`
- Optional: `ENTRA_ISSUER`, `ENTRA_JWKS_URL` (auto-derived if omitted)
- `AUTH_FALLBACK_USER_ID`

Behavior:

- Validates bearer token with JWKS and issuer/audience checks.
- Maps successful external identity to local fallback user.

## Redis + Traffic Controls

### Redis

- `REDIS_ENABLED=true|false`
- `REDIS_URL=redis://localhost:6379/0`

If Redis is unavailable, cache and rate limiter fall back to in-memory mode.

### Caching Middleware

- `CACHE_ENABLED=true|false`
- `CACHE_DEFAULT_TTL_SECONDS=30`
- `CACHE_MAX_BODY_BYTES=1048576`
- `CACHE_INCLUDE_PATHS=/api/v1/health`
- `CACHE_EXCLUDE_PATHS=/docs,/openapi.json,/redoc`

Rules:

- Only GET requests are cached.
- Authenticated requests (`Authorization` header) are not cached by default.

### Rate Limit Middleware

- `RATE_LIMIT_ENABLED=true|false`
- `RATE_LIMIT_REQUESTS=120`
- `RATE_LIMIT_WINDOW_SECONDS=60`
- `RATE_LIMIT_EXEMPT_PATHS=/docs,/openapi.json`

## DB and Startup

- `POSTGRES_DSN`, `ORACLE_DSN`, `MONGODB_DSN`, `MONGODB_DB_NAME`
- `SKIP_STARTUP_DB=true|false`

Use `SKIP_STARTUP_DB=true` in CI/tests when live DB services are not required.

## Do / Do Not

Do:

- Keep secrets in a secret manager in production.
- Set strong `JWT_SECRET_KEY` and rotate keys.
- Restrict `CORS_ORIGINS` and `ALLOWED_HOSTS` to real domains.
- Pin `AUTH_PROVIDER` explicitly per environment.

Do not:

- Commit real keys or Entra tenant secrets to git.
- Use `AUTH_FALLBACK_USER_ID` that points to a disabled user.
- Enable broad cache on user-specific endpoints without cache key segmentation.
- Leave rate limiting disabled on public internet deployments.
